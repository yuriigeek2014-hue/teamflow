Практичні ситуації

Робочі кейси команди

Як команда вирішує проблеми під час розробки сайту.

CASE-01

Кнопка виходить за межі картки

Після зміни розмірів екрана кнопка виходить за межі свого контейнера.

  • FrontEnd
  • QA
  • Designer
План команди
  1. QA показує ширину екрана та кроки відтворення.
  2. FrontEnd перевіряє width, padding і min-width.
  3. Designer підтверджує поведінку довгого тексту.

CASE-02

Інтерфейс неправильно відображається на телефоні

Частина елементів сторінки не поміщається на мобільному екрані.

  • FrontEnd
  • Designer
  • QA
План команди
  1. QA перевіряє сторінку на різних розмірах екрана.
  2. Designer адаптує макет для мобільної версії.
  3. FrontEnd виправляє CSS та перевіряє адаптивність.

CASE-03

Клієнт змінив назви всіх кнопок

Нові назви кнопок стали довшими, тому частина тексту перестала вміщуватися.

  • Product Manager
  • Designer
  • FrontEnd
  • QA
План команди
  1. Product Manager уточнює нові назви кнопок та погоджує їх із клієнтом.
  2. Designer оновлює макет, перевіряє довжину тексту та розміри кнопок.
  3. FrontEnd адаптує CSS, а QA перевіряє всі кнопки на різних розмірах екрана.
